### 3.2 记忆注入顺序(KV Cache 友好)

```
soul(稳定,可关) → rule_basic(稳定,必注) → OTACO流程 → 工具列表(稳定)

  → 当前时间(最易变)
```

### 3.3 混合检索(BM25 + RAG,3:7 权重)

- **BM25**:MySQL FULLTEXT + ngram 解析器(中文分词),top-10 召回
- **RAG**:Chroma cosine 向量检索,top-10 召回
- **融合**:min-max 归一化后 3:7 线性加权,取 top-5
- Python 子服务不可用时,Go `RetrieveProjectMemories` 降级为 MySQL `ListByProject`(无相关性排序)

### 3.4 记忆自动提取(混合策略)

- **关键词即时提取**(每轮):对话结束 → Python /extract_keywords → Go 端去重拦截 → 入库(memory_type=keyword, importance=30)
- **LLM 深度提取**(累计5轮):每 5 轮触发一次,LLM 输出结构化 JSON [{content, type, importance}]
- **Go 端去重拦截**:写入前调 Python /search 查同项目相似记忆,**cosine > 0.92 判重**;命中则更新 importance(+5,上限100)+ last_accessed_at,不新增记录
- **importance 评分**:事实记忆初始 50,关键词初始 30;每次被检索命中 +5(上限 100)

### 3.5 TTL 归档(单条记忆级)

- **定时任务**:[memory/ttl_scheduler.go](../agent-go/internal/memory/ttl_scheduler.go) 每周一 Asia/Shanghai 03:00 执行;分批100条迁移 + 批间微停100ms;跳过已归档项目
- **高价值记忆豁免**:importance>=80 的项目记忆不自动归档,只能手动归档
- **并发保护**:定时任务与手动触发互斥(running 标志 + sync.Mutex);同时调用时后者返回 409 Conflict
- **失败重试**:某批事务失败时跳过继续,全部归档完成后对失败批重试最多 3 次
- **归档**:POST /memory/memories/:id/archive — 事务内迁移到 agent_memory_archive + 硬删主表;事务外删 Chroma 向量;30 天内可恢复

### 3.6 @跨项目读取

仅限 @ 自己的项目,无需授权流程:

- **解析**:[memory/service.go](../agent-go/internal/memory/service.go) `ParseCrossProjectRefs` 正则匹配 `@项目名`
- **校验**:[memory_repo.go](../agent-go/internal/storage/memory_repo.go) `FindByName(ownerID, name)` 按 owner+项目名精确查询;非自己项目返回 nil 静默跳过
- **注入**:BuildMemoryBlock 末尾,对每个 @项目名检索跨项目记忆 top3,注入"## 跨项目参考(@项目名)"块

### 3.7 滑动窗口压缩 + 上下文占比 + 消息 TTL(2026-07-30 完成)

**窗口=10轮,窗口外由 LLM 异步压缩,上下文超 80% LLM 自主调用工具,超 90% Go 端强制压缩,压缩后 7 天未恢复的消息软删**。

| 设计点 | 实现位置 | 说明 |
|---|---|---|
| 窗口大小 | [otaco_storage.go](../agent-go/internal/orchestrator/otaco_storage.go) `defaultSlidingWindow=10` | loadHistory 只加载最近 10 轮完整消息 + summary |

## 五、阶段四:工具扩展(2026-07-31 完成)

### 5.1 三层工具模型设计

按"使用频率 × schema 复杂度"决定每个工具走哪一层:

| Layer | 适用场景 | 阶段四工具 | context 占用 |
|---|---|---|---|
| Layer 1: FC 常驻 | 高频 + 简单 schema | file_read / file_write / grep / sandbox_exec | 100-300 tokens/工具 |
| Layer 2: Skill 按需加载 | 低频 + 复杂 schema | Knovis 社交操作(6 个工具) | ~25 tokens(仅元信息) |
| Layer 3: MCP 网关 | 低频 + MCP 外接 | (瑞幸已移除,预留) | ~25 tokens(仅元信息) |

- **load_skill** 本身是常驻 FC 工具,模型调 `load_skill("knovis")` 后系统返回详细 schema 注入下一轮
- **Skill 加载后常驻到对话结束**(不卸载),避免反复加载
- **Skill 注册表**注入 system prompt 末尾(工具列表后、记忆块前),KV Cache 友好
- **审批流放执行层**不放 context 层:NeedsApproval 工具在 processToolCalls 拦截,运行时通过 ApprovalManager 走审批队列

## 六、记忆层完整设计决策(2026-07-29 深度对齐)

> 后续实施必须遵循的 20 项设计决策。

**A. 基础架构层(6项)**:
1. Project 概念模型:独立表(保持当前 agent_projects),Session 通过 project_id 外键挂靠,不做成 session 自引用
2. Session 归属:创建时确定 project_id(可空),之后不可变;chat.go 去掉请求体 project_id 参数,只认 session.project_id
3. 删除 Project:事务级联软删子 session + messages + 删 Chroma collection(3 步原子)
4. 无项目 Session:允许 project_id 为空,此时仅注入全局记忆(user 档案 + rule_basic),无项目记忆
5. 项目归档(is_archived=true):停用记忆注入,session 仍可对话但跳过 RAG;BuildMemoryBlock 检查 is_archived
6. Session 归属校验:createSession 时校验 project_id 归属当前用户(owner_id == client_id),多用户防越权

**B. 记忆权限与隔离(1项)**:
7. 严格 owner 隔离:记忆 owner_id = 创建者,仅 owner 可读/写/删;检索时仓储层强制 WHERE owner_id = ? 过滤;跨用户泄露是 P0 级问题

**C. Redis 缓存层(1项)**:
8. 检索结果不缓存:不同 query 命中同一缓存会返回错误结果;Redis 仅缓存 user_config(30min) + project_info(10min)

**D. Python 子服务(1项)**:
9. 鉴权:暂不加,仅内网监听 127.0.0.1;留到 P3 多用户阶段加固定 API Key 或 token

**E. Go 记忆服务(3项)**:
10. RetrieveProjectMemories 优化:直接用 Python /search 返回结果(含 content/memory_type/source/importance/score),省 N 次 MySQL 查询
11. memoryBlock 构建:每对话构建一次,OTACO 多轮迭代用同一个 system prompt(KV Cache 友好,不随对话演进重建)
12. 记忆 content 更新同步:更新 content 后自动标记 embedding_status=pending,下次达 embed 阈值时重新生成 Chroma 向量(最终一致)

**F. 记忆自动提取(混合策略,5项)**:
13. 关键词即时提取:Python 新增 /extract_keywords 接口(jieba 分词 + 停用词 + TF-IDF),每轮异步调
14. 关键词存储:存入 agent_memories(memory_type=keyword, importance=30),走统一 embed + 检索链路;不单独建表
15. LLM 深度提取:累计5轮批量触发,输出结构化 JSON [{content, type, importance}]
16. 记忆去重(Go 端拦截):写入前调 Python /search 查同项目相似记忆(cosine > 0.92 判重);命中则更新 importance + last_accessed_at 不新增
17. importance 评分:事实记忆初始 50,关键词初始 30;每次被检索命中 +5(上限 100);用户可手动调整

**G. @跨项目读取(1项)**:
18. @前缀解析项目名,仅限 @ 自己的项目(owner_id 校验);@ 他人项目直接 403;不需要 ask_user 授权流程

**H. TTL 归档(单条记忆级,1项)**:
19. 归档对象:agent_memories 中超14周未被检索命中的记忆条目;归档操作:迁移到 agent_memory_archive + 删 Chroma 向量(3步原子事务);30天内可恢复回主表 + 重新 embed

**I. 数据库与备份(1项)**:
20. 不做主备:保持单 MySQL 实例 + Redis 缓存 + Chroma 向量库;等记忆量真的大到性能瓶颈时再考虑主从复制

**J. 安全/并发 P0 防护(项目95%完成后统一做,5项)**:
- [ ] embed 重复触发:Redis 分布式锁(SETNX memory:embed:lock:{projectID})
- [ ] Redis 缓存击穿:互斥锁(singleflight 或 Redis SETNX)
- [ ] 删除级联不一致:事务包住所有级联操作
- [ ] 跨用户数据泄露:仓储层强制注入 owner_id 条件
- [ ] 网络攻击防护:SQL 注入(GORM 参数化)+ XSS(前端转义)+ CSRF + 限流
