## 一、历史问题修复记录

以下问题在前期开发中已修复,记录备查:

| 问题 | 根因 | 修复位置 |
|---|---|---|
| 第二轮 LLM 调用失败(400 Invalid assistant message) | 加载历史时包含空 content 的 observe 阶段 assistant 消息 | [otaco_storage.go](../agent-go/internal/orchestrator/otaco_storage.go) 跳过 Stage="observe" 消息 + 空值检查 |

| 轮次不连续 | 新对话从 1 开始,未接续历史 maxRound | loadHistory 返回 maxRound,新轮次 = baseRound+iteration+1 |
| 会话标题/图标颜色过淡 | 浅色背景下用 #e5e7eb / #9ca3af | [index.html](../agent-go/static/index.html) 改用 var(--text) / var(--text-secondary) |
| 最终回答重复显示 | handleDoneEvent 同时在主气泡和 Output 卡片渲染 | Output 卡片改为显示 "✓ 已生成最终回答" 状态提示 |
| agent-go 部署环境变量不生效 | `conf.MustLoad` 未启用 `conf.UseEnv()`，yaml 中 `${VAR:-default}` 占位符不展开（start.sh 传的环境变量全部失效） | [main.go](../agent-go/cmd/agent/main.go) 增加 `conf.UseEnv()` 选项 |
| 旧库缺新表/新字段（`memory_search_metrics` + `agent_memories` 5 字段） | start.sh 仅在表数<5 时导入 docker-init.sql，已有旧库不补增量 | [migrate-upgrade.sql](../deploy/paratera/migrate-upgrade.sql)（幂等，信息 schema 判断 + 动态 SQL）+ [start.sh](../deploy/paratera/start.sh) 每次启动无条件执行 |
| `.env.paratera` 占位值易漏替换 | 5 个 key 为 `please-generate-...` 占位 | [.env.paratera](../deploy/paratera/.env.paratera) 顶部标注"🔴 部署前必改 + openssl 生成方式" |
